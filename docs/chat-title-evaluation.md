# 대화 제목 생성과 정확도 평가

첫 답변이 끝나면 같은 모델이 첫 질문을 요약해 제목을 생성합니다. 실패·미지원·시간 초과 때는 질문의 첫 줄을 사용합니다. 수동으로 정한 제목은 자동 결과보다 우선합니다. 별도 제목 모델은 필요하지 않으며 `LLM_TITLE_ENABLED=false`로 추가 호출을 끌 수 있습니다. 설정은 개별 실행의 `backend/.env`, Compose의 루트 `.env`에 지정합니다.

## 무엇을 자동으로 확인하는가

| 검사 | 의미와 한계 |
| --- | --- |
| JSON·길이·한 줄·언어 | 제목 필드 하나와 2~60자 범위를 검사합니다. 질문에 한국어가 있으면 제목에도 한국어를 요구합니다. |
| 자격 증명·위험한 표시 | 공통 비밀값 마스킹과 현재 모델 키 검사로 의심되는 출력을 거절합니다. 모든 개인정보를 탐지하는 시스템은 아닙니다. |
| 질문에 없는 숫자·완료 주장 | 질문에 없는 수치나 완료·검증 주장을 추가한 후보를 거절합니다. 문장의 모든 사실을 검증하지는 않습니다. |
| 주제 단서 | 질문과 공유하는 단어나 한국어 부분 문자열이 없으면 거절합니다. 자연스러운 바꿔 쓰기가 거절되거나 관련 없는 문장이 통과할 수 있습니다. |
| 평가셋의 주제 단어 | 질문별 필수 주제 그룹과 금지 표현을 대조합니다. 이는 어휘 기반 보조 지표입니다. |

이 결과를 모델의 자신감이나 의미 정확도 백분율로 표시하지 않습니다. 저장된 `checks.semantic_verified`는 `false`, 평가 보고서의 `semantic_accuracy`는 `null`입니다. 규칙을 통과했다고 사실에 맞는 제목으로 인증한 것은 아닙니다.

## 평가 명령

가상환경을 활성화하고 `backend` 디렉터리에서 실행합니다. Termux에서는 사용 중인 Python 버전에 맞는 `LD_PRELOAD`를 [설치 안내](../TERMUX.md)에 따라 명령 앞에 적용합니다. 패키지는 기존 requirements를 사용합니다.

```bash
cd backend

# 사람이 작성한 기준 제목 16개의 평가 규칙만 검사합니다. 모델 호출은 없습니다.
python evaluate_titles.py --reference

# 실제 앱에 등록된 연결·모델을 사용합니다. 실제 계정과 모델 ID로 바꾸세요.
python evaluate_titles.py --connection office --username YOUR_USERNAME \
  --model ACTUAL_MODEL_ID --output title-evaluation.json

# 별도로 수집한 모델 제목도 평가할 수 있습니다.
python evaluate_titles.py --responses responses.json --output title-evaluation.json
```

`responses.json`은 평가셋의 case ID를 키로 하는 JSON 객체입니다. 예: `{"auth":"FastAPI 로그인 토큰 오류 분석"}`. 누락된 사례는 실패로 집계합니다. 질문·기준 제목·주제 그룹은 [chat_titles.ko.json](../backend/evaluations/chat_titles.ko.json)에 있습니다.

실제 연결 모드는 등록된 활성 계정의 모델 접근 권한과 기존 사용량·동시 처리 한도를 적용합니다. 질문마다 최대 한 번 호출하며 테스트 연결은 거절합니다. 모델 서버가 필요하고 그 호출도 토큰 사용량에 포함됩니다. 실패한 사례는 합격에 포함하지 않습니다.

## 의미 정확도를 판단하는 방법

1. 실제 사용자 요청을 익명화해 대표 질문을 만듭니다. 한국어·영어, 짧은 질문·긴 질문, GitLab·코드·문서·이미지·일반 대화와 주제 전환을 포함합니다. 현재 16개 공개 사례는 출발점이며 운영 질문의 분포를 대표한다고 단정하지 않습니다.
2. 각 질문에 반드시 남아야 할 주제와 추가하면 안 되는 사실·수치·완료 주장을 사람이 적습니다. 정답 제목의 글자 일치 대신 같은 의도를 표현하는 다른 제목도 허용합니다.
3. 실제 배포 모델·서빙 설정으로 제목을 수집합니다. 모델·버전·출력 설정·날짜를 함께 기록하고 사람이 작성한 기준 제목의 검사 결과와 구분합니다.
4. 각 제목이 핵심 주제와 요청 의도를 보존하는지, 새 사실이나 완료 주장을 만들지 않았는지, 언어와 가독성이 적절한지, 민감정보가 없는지 검토합니다. 가능하면 두 사람이 독립 평가하고 불일치를 검토합니다.
5. **의미 합격률 = 사람이 합격으로 판정한 사례 수 / 전체 질문 수**로 보고합니다. 모델 호출 실패·빈 결과는 전체 분모에 남겨 둡니다. 별도로 호출 실패율·질문 기반 제목으로 복구한 비율·자동 규칙 통과율도 제시합니다.

현재 로컬 검증은 사람이 적은 기준 제목 16개의 규칙 검사와 모의 모델의 HTTP 계약 검사입니다. 실제 배포 모델의 의미 합격률은 측정하지 않았습니다. `16/16` 규칙 통과를 실제 모델 정확도 `100%`라고 해석하면 안 됩니다.

## 전체 AI 작업의 정확도와의 관계

제목 평가만으로 본문 답변·도구 선택·코드 수정의 정확도를 알 수 없습니다. 일반 답변은 확인 가능한 출처와 정답셋, RAG는 검색 근거와 인용 일치, GitLab 개발은 실제 Diff·테스트·게시 영수증으로 각각 검증해야 합니다. 도구 실행 성공과 내용의 정답 여부도 구분합니다. 기존 실행·권한 회귀 검사는 [검증 기록](../VALIDATION.md)에 있고, 이 제목 평가 명령이 범용 답변 정확도를 계산하지는 않습니다.

## 동작과 운영 제약

- 제목 생성은 첫 답변 완료 후 한 번 실행합니다. 후속 질문·답변 재생성마다 호출하지 않습니다.
- 출력은 최대 256토큰, 기본 전체 제한 시간은 대기열을 포함해 20초입니다. JSON 스키마 출력을 거절하는 서버에서는 질문 기반 제목을 유지합니다.
- 첫 질문을 제한된 길이로 전달하므로 아주 긴 질문의 뒷부분 주제가 빠질 수 있습니다. 첨부 내용만으로 대화 제목을 붙이는 기능은 포함하지 않습니다.
- 제목을 기다리는 동안 다른 대화를 계속할 수 있습니다. 새로고침 후 저장된 제목과 작업 상태를 다시 읽습니다.
- 자동 제목은 별도 보조 테이블에 저장하고 기존 대화 정렬 시각을 바꾸지 않습니다. 수동 이름 변경·작업 만료·모델 권한 회수는 저장 직전에 재검사합니다.
- 본문과 제목의 사용량·추론 문맥을 분리합니다. 제목 호출도 모델 자원을 사용하므로 운영 통계의 전체 요청 수가 늘어납니다.
